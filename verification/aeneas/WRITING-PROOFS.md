# Writing Aeneas + Lean proofs in this repository

Read this before adding a proof. The overview is in [README.md](README.md);
the controller and pool extraction crates are in
[docs/extraction.md](docs/extraction.md).

## Layout

| Path | Contents |
|---|---|
| `Cargo.toml`, `src/`, `shim/` | Extraction crate for `common/src/math`, `common/src/rates` (`RatesAeneas`) |
| `pool/`, `controller/`, `oracle/` | One extraction crate per area: own Cargo workspace and shim |
| `lean/` | One Lake project; a library per crate: `RatesAeneas`, `PoolAeneas`, `ControllerAeneas`, `OracleAeneas` |
| `lean/<Lib>/Types.lean`, `Funs.lean` | Generated by Aeneas; never edit |
| `lean/<Lib>/TypesExternal.lean`, `FunsExternal.lean` | Hand-written meaning of what Aeneas leaves opaque. **Trusted base** |
| `lean/<Lib>/Proofs/*.lean` | Theorems |
| `lean/FixedPoint/` | The rounding specifications `IsFloor`, `IsCeil`, `IsHalfUp` and their pure-integer lemmas, shared by the rates, pool and controller libraries (Mathlib only) |
| `lean/Audit.lean` | `#assert_standard_axioms`, run at the end of every library root |
| `check_standins.py` | Compares a crate's copied production code with production |
| `sync_copies.py` | Writes renamed copies of RatesAeneas proofs (`--check` fails on a stale one) |
| `docs/<area>.md` | Per-area theorem documentation |

## Pipeline

1. A crate compiles the production files **verbatim** through `#[path]`
   includes.
2. `soroban_sdk` is renamed to a shim crate. Charon translates only the
   signatures of items from another crate, so every shim item is opaque to
   Aeneas; its meaning lives in `FunsExternal.lean`.
3. `charon cargo --preset=aeneas --dest-file target/llbc/<crate>.llbc`
4. `aeneas -backend lean -dest lean/<Lib> -split-files target/llbc/<crate>.llbc`;
   copy new external declarations into `FunsExternal.lean`/`TypesExternal.lean`,
   then delete the `*_Template.lean` files.
5. `cd lean && lake build <Lib>`.

`AENEAS_HOME` is the unpacked Aeneas release (it contains `charon` and
`aeneas`); setup is in [README.md](README.md#setup). Keep build output inside
the worktree.

## Conventions

* **State the claim about the generated `Funs.lean` definition** of the
  production function, not a model.
* **Total correctness.** Write `f args ⦃ r => P r ⦄` (`f` returns and `P`
  holds). A theorem about an error path states the failure explicitly.
* **Specifications never divide.** "q = ⌊n/d⌋" is
  `FixedPoint.Spec.IsFloor n d q` (`q*d ≤ n < q*d + d`, `d > 0`). Write
  siblings (ceiling, half-up, …) in the same style.
* **No `sorry`, `admit` or new `axiom`.** The only allowed axioms are
  `propext`, `Classical.choice` and `Quot.sound`. Every library root ends with
  `#assert_standard_axioms <Lib>`, which also fails if a file under `<Lib>/`
  is not imported from the root (`run.sh` re-runs it outside Lake's cache).
  Leave out a claim that cannot be proved and list it, with the reason, under
  "Not covered" in the area doc.
* **Include production code with `#[path]`.** When an item has to be copied
  into a stand-in, add it to `check_standins.py` (verbatim, subset, or pinned
  hash for an adaptation), so a production change to it fails `run.sh`.
* **State hypotheses as production-like domains**, saying why each holds at the
  call sites (e.g. "every index is ≥ 10^24, see `SUPPLY_INDEX_FLOOR_RAW`").
* **Document every theorem twice:** a plain-English doc comment (`/-- … -/`),
  and a row in `docs/<area>.md` with the Rust function, claim, hypotheses and
  the invariant IDs from `docs/reference/invariants.md` it supports.
* **External definitions follow the documentation of what they model** (Rust
  core docs, the Soroban host), and each comment says so.

## Pitfalls already solved

* **Checked signed operations are sealed.** `I128.checked_mul`,
  `checked_div`, `checked_sub` etc. are hidden under Lean's module system;
  their specs use the internal `core.num.checked_*_IScalar`. Make such proof
  files plain (`import …`, no `module` line), then
  `rw [show I128.checked_div p d = core.num.checked_div_IScalar p d from rfl]`
  and use `I128.checked_div_bv_spec p d` (a `match` on the result; `cases` on it).
* **`step` side goals.** After `step as ⟨x, hx⟩` an undischarged
  precondition comes first; close it with a bullet. The `ne` default
  (`core.cmp.PartialEq.ne.trait_default`) leaves an `hEq` goal: close it with
  `simp [<the eq function>]`. Check the goal list with the trace_state tactic.
* **`if b then` after `cases b`** needs `simp only [↓reduceIte]` (or
  `Bool.false_eq_true, ↓reduceIte`) before `step` can see the call.
* **`def` constants** (`aeneas_soroban_shim.I256.MIN`) are atoms to `omega`:
  rewrite with `show MIN = -2^255 from rfl` first. Generated globals
  (`constants.production.shared.RAY`) are `irreducible`: `unfold`, then
  `rfl`/`simp`.
* **`<` on scalars** is `IScalar.lt_equiv` (`x < y ↔ x.val < y.val`); scalar
  bounds are `x.hBounds`; building a scalar from an integer is
  `IScalar.tryMkOpt`, characterised by `IScalar.tryMkOpt_eq`.
* **Literal powers in lemma instances** (`IScalar.tryMkOpt_eq .I128 (10 ^ k)`)
  can loop the elaborator: `generalize hx : (10 : Int) ^ k = x` first.
* **`nlinarith` cannot use `r ≠ 0`**: split into `0 < r` or `r < 0`
  (`lt_of_le_of_ne`).
* **Simp loops on divisibility.** `simp [Int.dvd_iff_emod_eq_zero]` loops with
  Mathlib's `EuclideanDomain.mod_eq_zero`; use `rw` or `simp only`.
* **Generated names live in the crate's namespace** (`rates_aeneas`); `open`
  it in proof files and `FunsExternal.lean`.

## Reusing the math proofs from another library

Each extraction crate generates its own, textually identical copy of the
`common` math it calls, under its own namespace, so a proof in
`RatesAeneas/Proofs` carries over by changing the namespace.

* If it carries over unchanged, add its file to `sync_copies.py` and run the
  script, which writes the copy (marked `GENERATED`); `run.sh` fails when a
  copy is out of date. Edit the RatesAeneas original, never the copy.
* If it needs changes (the pool and controller extractions differ from the
  rates one in places), copy it by hand into your library's `Proofs/` and say
  where it came from in the doc comment.

Code that does not mention generated definitions is not copied: the rounding
specifications live once in `lean/FixedPoint/` (`import FixedPoint.HalfUpSpec`,
`open FixedPoint.Spec`).
