# Writing Aeneas + Lean proofs in this repository

How the proofs under `verification/aeneas/` are built, the conventions every
proof follows, and the pitfalls already solved. Read this before adding a
proof. The overview and the list of proved theorems are in
[README.md](README.md).

## Layout

| Path | Contents |
|---|---|
| `Cargo.toml`, `src/`, `shim/` | Extraction crate for `common/src/math` and `common/src/rates` (Lean library `RatesAeneas`) |
| `pool/`, `controller/`, `oracle/` | One extraction crate per area, each its own Cargo workspace with its own shim |
| `lean/` | One Lake project. One Lean library per extraction crate: `RatesAeneas`, `PoolAeneas`, `ControllerAeneas`, `OracleAeneas` |
| `lean/<Lib>/Types.lean`, `Funs.lean` | Generated by Aeneas. Never edit by hand |
| `lean/<Lib>/TypesExternal.lean`, `FunsExternal.lean` | Hand-written meaning of everything Aeneas leaves opaque. **Trusted base** |
| `lean/<Lib>/Proofs/*.lean` | Theorems |
| `docs/<area>.md` | Per-area documentation of every theorem |

## Pipeline

1. A crate compiles the production files **verbatim** through `#[path]`
   includes. Nothing in `common/`, `contracts/` is copied or edited.
2. `soroban_sdk` is renamed to a shim crate. Charon translates only the
   signatures of items from another crate, so every shim item is opaque to
   Aeneas, and its meaning lives in `FunsExternal.lean`.
3. `charon cargo --preset=aeneas --dest-file target/llbc/<crate>.llbc`
4. `aeneas -backend lean -dest lean/<Lib> -split-files target/llbc/<crate>.llbc`,
   then delete the `*_Template.lean` files after copying any new external
   declaration into `FunsExternal.lean`/`TypesExternal.lean`.
5. `cd lean && lake build <Lib>`.

Tools: `AENEAS_HOME` is the unpacked Aeneas release (it contains `charon`
and `aeneas`), pinned in README.md. Lean through elan (`~/.elan/bin` on
`PATH`). Keep build output on disk inside the worktree.

## Conventions

* **State the claim about the production function, not a model.** Theorems
  are about the generated `Funs.lean` definitions.
* **Total correctness.** Write `f args ⦃ r => P r ⦄`: it means `f` returns
  (does not abort) and `P` holds. A theorem about an error path states the
  failure explicitly.
* **Specifications never divide.** "q is the floor of n/d" is
  `RatesAeneas.Spec.IsFloor n d q` (`q*d ≤ n < q*d + d` for `d > 0`). Add a
  sibling definition (ceiling, half-up, …) in your own spec file in the same
  style.
* **No `sorry`, `admit` or new `axiom`** in any proof file. Before finishing,
  `#print axioms` every headline theorem: the only allowed axioms are
  `propext`, `Classical.choice` and `Quot.sound`. A claim that cannot be
  proved is left out and listed under "Not covered" in the area doc with the
  reason.
* **State hypotheses as domains, close to production.** Say why each holds at
  the call sites (for example "every index is ≥ 10^24, see
  `SUPPLY_INDEX_FLOOR_RAW`").
* **Document every theorem** twice: a doc comment (`/-- … -/`) on the theorem
  in plain English, and a row in `docs/<area>.md` with the Rust function, the
  claim, the hypotheses, and the invariant IDs from
  `docs/reference/invariants.md` it supports.
* **External definitions follow the documentation of what they model** (Rust
  core docs, the Soroban host), and each carries a comment saying so.

## Pitfalls already solved

* **Checked signed operations are sealed.** `I128.checked_mul`,
  `checked_div`, `checked_sub` and friends are not exposed under Lean's module
  system, and their library specs talk about the internal
  `core.num.checked_*_IScalar`. Write proof files that need them as plain
  (non-`module`) files (`import …`, no `module` line). Then
  `rw [show I128.checked_div p d = core.num.checked_div_IScalar p d from rfl]`
  and use `I128.checked_div_bv_spec p d` (a `match` on the result; `cases` on it).
* **`step` side goals.** After `step as ⟨x, hx⟩` a precondition the tactic
  could not discharge comes first; close it with a bullet. The `ne` default
  (`core.cmp.PartialEq.ne.trait_default`) leaves an `hEq` goal: close it with
  `simp [<the eq function>]`. Check the goal list with `trace_state` instead of
  guessing.
* **`if b then` after `cases b`** needs `simp only [↓reduceIte]` (or
  `Bool.false_eq_true, ↓reduceIte`) before `step` can see the call.
* **Constants defined with `def`** (`aeneas_soroban_shim.I256.MIN`) are
  atoms to `omega`. Rewrite with `show MIN = -2^255 from rfl` first.
  Generated globals (`constants.production.shared.RAY`) are `irreducible`:
  `unfold` them, then `rfl`/`simp`.
* **`<` on scalars** is `IScalar.lt_equiv` (`x < y ↔ x.val < y.val`); scalar
  bounds are `x.hBounds`; building a scalar from an integer is
  `IScalar.tryMkOpt`, characterised by `IScalar.tryMkOpt_eq`.
* **Literal powers in lemma instances** (`IScalar.tryMkOpt_eq .I128 (10 ^ k)`)
  can loop the elaborator. `generalize hx : (10 : Int) ^ k = x` first.
* **`nlinarith` cannot use `r ≠ 0`.** Turn it into `0 < r` or `r < 0` first
  (`lt_of_le_of_ne`).
* **Simp loops on divisibility.** `simp [Int.dvd_iff_emod_eq_zero]` loops with
  Mathlib's `EuclideanDomain.mod_eq_zero`; use `rw` or `simp only`.
* **Generated names live in a namespace** named after the crate
  (`rates_aeneas`); `open` it in proof files and in `FunsExternal.lean`.

## Reusing the math proofs from another library

Each extraction crate generates its own copy of the `common` math it calls,
under its own namespace. The definitions are textually identical, so a proof
in `RatesAeneas/Proofs` carries over by changing the namespace. Copy the
proof into your library's `Proofs/` and say where it came from in the doc
comment.
