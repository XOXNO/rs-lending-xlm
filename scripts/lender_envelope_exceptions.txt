# Accepted lender-envelope violations -- the declared exception list for
# scripts/check_lender_envelope.py.
#
# WHAT THIS FILE IS
#
# Every (spoke, collateral, debt, provider) pair whose LT * u_P(c) * u_P(d) is
# at or above 1 / (1 + MARGIN) must either be fixed in configs/<network> or be
# declared here with the audit finding that tracks it and the largest product
# it accepts. The checker fails on an undeclared violation, on a line here that
# no longer violates (stale: drop the line in the change that fixes the pair),
# on a declared pair whose current product is above its max-product (plus
# 1e-6 for rounding): a declaration does not cover a pair that got worse, and
# on a declared pair whose max-product is more than 1e-3 above its current
# product (loose): headroom in the declaration would accept a worsening unseen.
#
# FORMAT (whitespace separated; the reason runs to the end of the line)
#
#   <network> <spoke id> <collateral> <debt> <provider contract> <finding id> <max-product> <reason>
#
# spoke id      the key in configs/<network>/spokes.json
# collateral    a listing name in that spoke (a market name in markets.json)
# debt          a borrowable listing name in that spoke
# provider      the full provider contract address the pair is evaluated for
# finding id    the audit id, for example S3-MC-1
# max-product   the LT * u_c * u_d this line accepts (the checker prints the
#               current value next to it); set it to the current product,
#               to within 1e-3, and raise it only on purpose
#
# network must have a configs/<network> directory, and the spoke and both
# listings must exist in that network's spokes.json, whether or not the run
# checks that network.
#
# S3-CR-1: the spoke 5 USDC dual-leg tolerance lever (Reflector CAFJZ... or
#          RedStone CA526...). The spoke 1 SolvBTC/xSolvBTC debt pairs were
#          closed by the BTC reference tolerance (+-4%) and the SolvBTC factor
#          cap (1.03).
